# Расчёт асимптотики

Пусть `n` - количество строк, `m` - количество столбцов

| Задача | Время `solve` | Дополнительная память `solve` |
|---|---|---|
| 49 | `O(nm)` | `O(n)` |
| 50 | `O(nm)` | `O(m)` |
| 51 | `O(nm)` | `O(n)` |
| 52 | `O(nm)` | `O(m)` |
| 54 | `O(n)` | `O(1)` |
| 55 | `O(n)` | `O(1)` |
| 58 | `O(nm)` | `O(nm)` |
| 59 | `O(1)` | `O(1)` |

## Обоснование

Задача 49: внешний цикл проходит `n` строк, внутренний перебирает `m` элементов каждой строки, результат занимает `n` значений типа `long`

Задача 50: каждую из `n` строк обходим по `m` столбцам, для сумм храним `m` значений типа `long`

Задача 51: максимум каждой строки ищется за `O(m)`, всего `n` строк и `n` ответов

Задача 52: `clone()` копирует `m` значений первой строки, остальные `n - 1` строк сравниваются по `m` столбцам, поэтому итог `O(nm)`

Задачи 54 и 55: проверки формы матрицы требуют `O(n)` по числу строк, цикл суммирует ровно `n` значений диагонали, дополнительные массивы не создаются

Задача 58: создаётся массив `n*m` и каждый элемент заполняется один раз

Задача 59: матрица имеет фиксированный размер 3 на 3, а вложенные циклы выполняют всего девять итераций, поэтому время и память постоянны

## Уточнение по вводу данных

Таблица выше относится к вычислению ответа в `solve`, без хранения уже полученной входной матрицы

Для задач 49-55 чтение исходной матрицы занимает `O(nm)` времени и `O(nm)` памяти
Поэтому запуск всей программы `run` для задач 54 и 55 имеет сложность `O(n^2)` по времени и памяти при квадратной матрице, хотя сам алгоритм диагонали работает за `O(n)`

Для задачи 59 размер фиксирован, поэтому ввод и вычисление имеют сложность `O(1)`

У задачи 58 матрица создаётся непосредственно в `solve`, поэтому память `O(nm)` уже учтена

Для сумм в задачах 49, 50, 54 и 55 используется `long`, для определителя в задаче 59 - `BigInteger`
